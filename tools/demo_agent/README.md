# 問い合わせ一次対応エージェント（デモ）

**AIエージェント案件を取るための実演用。** 提案の場でそのまま動かす。

「AIエージェントで何ができるか」を言葉で説明しても中小企業には伝わらない。
自社と同じ業種の、自社と同じ仕事が目の前で処理されるのを見せるのが早い。

題材は**板金加工業の見積依頼メールの一次対応**。どの製造業にも同じ形の仕事があり、
どこも人がやっている。

## 動かす

```bash
python3 tools/demo_agent/agent.py            # inbox/ の全件
python3 tools/demo_agent/agent.py --only 001 # 1件だけ（デモ中に見せるならこちら）
```

実行ログは `out/run-<日時>.json` に残る。処理件数・所要時間・失敗件数が入っているので、
記事や提案書に書く数字はここから取る（**推定値を書かない**）。

## 設計 — ここが提案の中身

**AIに判断させない。AIは読み取りと作文だけ担当する。**

| 工程 | 内容 | 担当 |
|---|---|---|
| 1 | メール本文 → 構造化（材質・板厚・加工・数量・納期） | **AI** |
| 2 | 設備マスタと照合して受注可否を決める | Python（ルール） |
| 3 | 過去案件から類似案件を探し、単価の目安を出す | Python（検索） |
| 4 | 返信文の下書きを書く | **AI** |
| 5 | 情報が足りないもの・納期が合わないものを人間に回す | Python（ルール） |

「加工できるか」「いくらか」をAIに判断させると、もっともらしい嘘が混ざる。
設備マスタに無い板厚を「対応可能です」と返信した時点で、この仕組みは会社にとって
損失にしかならない。**判断は自社データとルール、AIは文章の入口と出口だけ。**

もうひとつの設計判断: **過去単価を返信本文に書かせない。**
条件が違えば当てにならないうえ、自動返信で客に出した金額は事実上の提示価格になる。
参考単価は担当者へのメモ（`internal_note`）に回し、値決めは人間に残している。

判断できないものは `escalate` として人間に回し、**下書きも作らない**。
人間が判断すべき案件に下書きが付いていると、そのまま送られる事故が起きる。

## ファイル

```
data/equipment.csv   設備マスタ（対応材質・板厚・最短納期）
data/past_jobs.csv   過去案件（材質・板厚・加工・単価）
inbox/*.txt          問い合わせメール
out/run-*.json       実行ログ
```

## ⚠ データはすべて架空

`data/` と `inbox/` は実在の企業・取引ではない。デモ用に作ったもの。
記事や提案でこの結果に触れるときは、**架空データでの実行であることを必ず明記する**。
実測なのは処理時間・自動化率・失敗件数だけで、業務効果ではない。

実導入では、`data/` の2ファイルを客の実際の設備一覧と受注履歴に差し替える。
そこが差し替われば、この構成のまま動く。
